# AGENTS.md

Guidance for AI agents working in this project. Humans: [README.md](README.md) says how to use the set, [SPEC.md](SPEC.md) describes the icon rules, [STRUCTURE.md](STRUCTURE.md) says how the set is organised.

## What this is

A pnpm workspace (`autosvg`): an agentic suite for producing vectors. Its first body of work is a **pure line icon set**: 24px grid, 1.5px stroke, round caps and joins, no fills, no backgrounds. TypeScript in strict mode, Biome for format and lint. The app (`apps/studio`) is a React app with four pages: **Library** (`/`, the set, search, and for the selected icon its motion and state player, the old Motion page), **Studio** (`/studio/<vector>`, the 24×24 canvas with keylines, checks, sizes, neighbours, SVG source), **Showcase** (`/showcase`, the carried icon in 3D, in real places, and in many styles grouped by industry) and **Quality** (`/quality`, the whole-set checks). The app exposes `window.autosvg` (a headless engine, `packages/engine`) so an agent can draw, measure and compare.

```bash
pnpm dev                # or preview_start "autosvg"; http://localhost:5173
pnpm seed               # regenerate the vector files from recipes + the pose table (pnpm seed:check to verify only)
pnpm css                # regenerate poses.css (only if the number of pose channels or beats changes)
pnpm quick a b          # recipe geometry check from the numbers, no browser (seed runs it too)
pnpm geom "pp.transform(kit.rect(4,10,16,4,2),{rotate:[-45]})"   # rotate/union/subtract shapes, prints paste-ready paths
pnpm verify-vectors a b --sheet --motion   # check and draw vectors in headless Chrome (~5 s); then look at .cache/vectors/*.png
pnpm check              # Biome, tsc in every package, and seed:check: must pass before a commit
```

New icons go in a batch file, `packages/core/src/batches/batch-<n>.ts` (recipes and poses together, registered at the bottom of `recipes.ts` and `poses/table.ts`). Helpers: `recipe-kit.ts`, `poses/dsl.ts`.

Packages (each depends only on the ones above it): `packages/vectors`, `packages/core`, `packages/runtime`, `packages/checks`, `packages/engine`, then `apps/studio` and `tools/`. They are consumed as source (no build step between them); Node runs the TypeScript in `tools/` directly, so relative imports carry the `.ts` extension.

## How to work

For any task about icons, the set, or the icon tooling, **use the `vector-craft` skill** and follow it. In short: read the lessons, draw with helpers, `verify`, `compare`, **look**, fix, repeat. Done means `verify` is `ok` **and** you looked at the 16/24/48px render and it is good.

## Rules that always apply

- **Work in the Studio page** (its inspector also shows the icon in each of its states) (`/studio/<vector>`, the one with the grid and keylines): load the icon, draw with `setSVG`/`append`/`patch` using `geo` and `pp`, look at the canvas, then `await autosvg.save()`. The app has no Save button and no style dropdown on purpose; don't add UI the user has to guess the purpose of. UI direction (user-set): spacious, less is more, no generic AI look; one neutral palette, status colour only where something needs attention. Don't create side views, full-screen overlays or contact sheets that cover it, and don't change icons by regenerating files from a script. The user is watching that page.
- Never run `node tools/src/legacy/build-vectors.ts --force`; it discards canvas edits.
- **Every new vector goes in one category** in `packages/vectors/src/categories.ts` (sorted; by what the thing is, not where it is used; a state is never listed). Do not add a category for fewer than about eight vectors. `pnpm check` fails otherwise.
- **Every icon has a pose, and it lives in the SVG** (see SPEC.md "Poses"). A new icon needs a recipe (if it has corners or circles) and an entry in `packages/core/src/poses/table.ts` with the right shape count and, where the object has them, its states (`withStates`): an icon is one icon with states, never two files like `mic` and `mic-off`, `arrow-left` and `arrow-up`, `play` and `pause` (a state can bring new elements in, turn or mirror the whole icon with a group, or redraw parts), then `pnpm seed`, then `autosvg.poseLint()` and `autosvg.perfAudit()` must pass (and `a11yAudit()` for any UI that uses icons) (`audit()` runs the performance audit too). Motion and state must make sense: a state is a real persistent condition of the object, a motion a real verb (when in doubt, leave it out). A lid hinges, a clapper lags, strokes draw in the order a hand would), stay inside the canvas at every value up to 1.25, and look right in the Library player's frames. Never write a pivot by guessing a shape's position: check the shape order first.
- **This is a library used by many consumers. Ship parameters, not behaviours.** The library exposes numbers as CSS variables (`--icon-radius`, `--icon-pose`, `--icon-glint`, easing and duration tokens); the consumer decides when they change (hover, selected, loading, scroll, pointer, its own script). Don't build triggers, pointer tracking or choreography into the library. Anything motion-related must work by a consumer setting a variable on any ancestor, and must respect `prefers-reduced-motion`.
- Pure line only. Don't add fills, tints, dots as shapes, backgrounds, or extra UI chrome unless the user asks.
- Don't guess a visual direction. If it is not settled, show 3 small samples first.
- Install dependencies with a bare `pnpm add <pkg>` (no redirects or pipes) after vetting with `guardPackage`. Versions live once in the `catalog:` of `pnpm-workspace.yaml`; packages say `catalog:`.
- Code is strict TypeScript and Biome-clean: no `any`, no non-null `!`, no suppression without a reason. `pnpm check` must pass.
- Don't claim a tool or fix works until you ran it. Report what you saw, including flaws, and what you did not test.

## Self-correction protocol

This project gets better through a feedback loop. You are responsible for running it.

**Auto-correct a piece of work (inside a task)**

1. Run `await autosvg.verify(autosvg.getSVG())` on what is in the canvas. Apply every hint. Re-run. Repeat until `ok`.
2. Screenshot the Studio page and look: full size, the 16 to 48px previews, and the icon in the "Beside its neighbours" strip. If it looks wrong, fix it in the canvas and go back to step 1.
3. Maximum 4 rounds per icon. Then stop, state what is wrong and what you tried, and ask. Never ship a shape you dislike, and never loop silently.
4. After a batch, run `await autosvg.audit()` and handle every flagged icon or say why it is deliberate.

**Learn (after a task, or immediately on a trigger)**

Triggers: the user corrects you or expresses dissatisfaction; a check you trusted was wrong (false positive or false negative); a tool behaved unexpectedly; an approach clearly worked or clearly failed.

1. Write a lesson in `.claude/skills/vector-craft/references/lessons.md` using its format. Include the evidence: a measurement, a screenshot description, or the user's words. No evidence, no lesson.
2. **Promote** a lesson into `SKILL.md` as a permanent rule when it has recurred, or it is general and high-impact. Mark it `promoted`.
3. **Retire or fix** lessons that prove wrong or outdated. Never keep two contradicting rules. Merge duplicates.
4. If a check or tool is the thing that was wrong, fix the tool (`packages/checks/src/lint.ts`, `packages/checks/src/measure/`, `packages/checks/src/paper-tools.ts`) and note it in the lesson. Calibrate checks against known-good and known-bad icons, as `verify` was calibrated.
5. User preferences (style, scope, UI) are rules, not suggestions. Record them as such and follow them over your own judgment.

**Keep the loop healthy**

- Keep `lessons.md` short: merge, don't pile up. If it grows past about 40 entries, consolidate.
- Never edit this file's rules on a hunch. Change AGENTS.md or SKILL.md only for a lesson you can point to evidence for.
- In your final message, say which lessons you read and applied, and which you added or changed.
